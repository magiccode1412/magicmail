# PR 变更总结

分析 PR 代码变更，生成结构化总结。

## 执行步骤

### 1. 获取变更信息

使用 PR diff 技能（cnb-pr-diff）：先取变更统计（`--stat`）与文件列表（`--name-only`），再按需取关键文件的 diff。

### 2. 过滤文件

**优先分析**（核心代码）：业务逻辑（`src/`、`lib/`、`app/`、`packages/`）、API/接口（`api/`、`routes/`、`controllers/`）、配置（`*.config.*`、`*.yml`、`*.yaml`）、数据库/模型（`models/`、`schema/`、`migrations/`）。

**跳过**：PR diff 技能（cnb-pr-diff）列出的排除类型；以及纯测试文件（除非测试是本次变更重点）。

### 3. 分析变更

分析维度：

- **变更类型**：feat / fix / refactor / perf / docs / chore
- **影响范围**：涉及模块与功能点
- **关键改动**：核心逻辑、API、数据结构变更
- **破坏性变更**：不兼容改动、需迁移的内容

上下文不足时读取完整源文件。

## 输出格式

```markdown
**{type}**: {一句话描述}

**主要改动**
- {模块}: {变更说明}
- {模块}: {变更说明}

**注意**: {破坏性变更或风险点；如无则省略}
```

## 总结原则

1. **简洁**：突出重点，不逐行复述 diff
2. **按功能分组**：按模块组织，不逐文件罗列
3. **突出意图**：说明"为什么改"，而非仅"改了什么"
4. **识别风险**：主动指出破坏性变更与关注点

## 大型 PR 处理

文件数超过 20 个时：
1. 用 `--stat` 分析变更分布，按模块归类
2. 重点分析核心模块（变更量大或涉及关键逻辑）
3. 末尾概括其余未详细分析的文件/模块
