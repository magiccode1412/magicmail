# 搜索并召唤 NPC 协同工作

通过自然语言描述语义搜索 CNB 平台上的公开 NPC 角色，找到最合适的 NPC；在确有需要时，按正确格式召唤 NPC 协同工作。

## 概念澄清

CNB 语境下 **NPC = 自动化角色**（AI 智能助手），与游戏中的 Non-Player Character 无关。按用户意图路由：

- 想找/召唤协同干活的 NPC → 用本 skill 搜索并召唤
- 问 `npc:go`（点分名称，内置任务）或 NPC 流水线配置 → 路由到 **cnb-pipeline** skill 的 `references/builtin-tasks.md`
- 想了解 NPC 概念、事件、工作模式 → 路由到 **cnb-docs** 查官方文档

## 使用边界

本 skill 含两个行为，**默认只做搜索**：

- **仅搜索**：用户只查询有哪些 NPC（如"有没有做代码审查的 NPC"）→ 列出候选及能力，**不输出 `@` 召唤语法**，等用户确认。
- **搜索并召唤**：用户明确要求召唤/委派，或当前任务确需其他 NPC 介入 → 在搜索结果基础上发起召唤。

## 何时需要召唤 NPC

以下情况可建议用户召唤其他 NPC：

1. **任务超出能力范围**：需要特定领域专家（如前端、测试、安全等）
2. **任务可拆解并行**：多个子任务可同时进行，或任务耗时长
3. **需要跨仓库协作**：涉及其他仓库的代码或功能
4. **其他 NPC 更擅长**：效率更高
5. **需求涉及多个专业领域**：需多个 NPC 分别覆盖

## 搜索步骤

### 1. 提炼需求描述

分析用户需求，将目标 NPC 能力提炼成**一句话描述**（后台基于 RAG 向量匹配而非关键词，描述越贴合需求匹配越准）。常见场景对应描述：

- 需要代码审查 → `擅长代码审查、能发现安全漏洞和代码质量问题的 NPC`
- 需要写前端 → `熟练使用 React 等框架进行前端界面开发的 NPC`
- 需要写测试 → `能为项目编写单元测试和测试用例的 NPC`
- 需要性能优化 → `擅长性能分析与调优、能提升运行效率的 NPC`
- 需要安全审计 → `熟悉安全审计、能排查安全隐患的 NPC`

### 2. 执行搜索

```bash
cnb knowledge-base search-npc --key "一句话需求描述"
```

可选参数：
- `--top-n <number>`：返回结果数量，最大 20（默认 10）

### 3. 解读搜索结果

搜索结果包含以下字段：

- `name`：NPC 角色名称
- `slug`：NPC 所在仓库路径
- `slogan`：NPC 简介/标语，描述其能力和特点
- `score`：语义匹配分数（越高越相关）
- `avatar`：NPC 头像路径

### 4. 选出最合适的 NPC

结合以下因素选出最合适的 NPC：

1. **匹配分数**（score）：越高越相关
2. **slogan 描述**：判断能力是否符合需求
3. **角色名称**（name）：通常反映专长领域

## 召唤 NPC

选定 NPC 后，使用正确的 @ 格式发起召唤：

```
@{slug}({name})
```

其中 `slug` 是仓库路径，`name` 是角色名。例如：
- `@npc/hok(π)` - 仓库 `npc/hok` 下名为 `π` 的 NPC
- `@npc/code-reviewer(代码审查员)` - 仓库 `npc/code-reviewer`

### 传递完整的上下文

召唤时提供：
- **任务背景**：要解决的问题
- **相关文件**：涉及的代码或路径
- **约束条件**：技术栈、代码规范等
- **期望结果**：交付物形式

示例召唤方式：

```
@npc/code-reviewer(代码审查员) 帮我审查 /workspace/src/auth 目录下的登录逻辑，重点关注：
1. 密码存储是否安全
2. Session 管理是否有漏洞
参考标准：OWASP Top 10
```

## 协同工作模式

召唤成功后，可分工协作（拆分任务并行处理）或串联审核（一个完成后另一个继续优化）。

## 约束速查

### 搜索
- 需求描述用一句话自然语言，具体、贴合目标 NPC 能力，避免过于宽泛；结果不理想时换一种表述重试
- 搜索命令可直接执行，无需用户确认

### 召唤
- 召唤需用户确认或有明确委派意图
- 召唤前先通过 slogan 了解目标 NPC 能力；slogan 为空时优先推荐有明确 slogan 的
- 尽量一次召唤到位，避免反复补充上下文
- 模糊需求先自行分析，再决定是否召唤；始终把控整体任务，即使已分配子任务
- 评论中只提及 NPC 不召唤时，去掉 `@` 或使用反引号包裹 `@npc`
